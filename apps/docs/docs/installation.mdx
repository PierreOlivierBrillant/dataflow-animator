## Installation

```bash
npm install @dataflow-animator/react
```

`react` and `react-dom` (≥ 18) are expected in `peerDependencies`.

[`@dataflow-animator/core`](https://www.npmjs.com/package/@dataflow-animator/core)
— the engine, the DOM renderer and the stylesheet — installs along with it as a
dependency. You never install it yourself, but you do **import the stylesheet
from it**: the React package ships no CSS of its own.

:::tip No React?
The core mounts on its own, in any page:
`mountPlayer(container, spec, options)`. The React package is a thin binding over
exactly that call.
:::

## Minimal usage

```tsx
import { DataFlowPlayer } from '@dataflow-animator/react';
import '@dataflow-animator/core/styles.css';

const spec = {
  direction: 'left-to-right',
  nodes: [
    { id: 'browser', type: 'laptop', text: 'Browser', lane: 1 },
    { id: 'api', type: 'server', text: 'API', lane: 2 },
  ],
  packets: [
    {
      id: 'req',
      kind: 'http_packet',
      packet_content: { header: 'GET /users' },
    },
  ],
  timeline: [{ type: 'move', object: 'req', from: 'browser', to: 'api' }],
};

export default function Example() {
  return <DataFlowPlayer spec={spec} />;
}
```

## In Docusaurus

Import the CSS once in `src/css/custom.css` then use the component in any MDX file:

```css title="src/css/custom.css"
@import '@dataflow-animator/core/styles.css';
```

```mdx title="docs/my-article.mdx"
import { DataFlowPlayer } from '@dataflow-animator/react';

<DataFlowPlayer spec={spec} mode="auto" />
```

The `auto` theme (default) follows `prefers-color-scheme` AND a `[data-theme]` ancestor (Docusaurus convention), so the component automatically syncs with the host's theme toggle.

## In Next.js (App Router)

The component uses `useState`/`useEffect`: mark the calling file as a client component.

```tsx title="app/example/page.tsx"
'use client';

import { DataFlowPlayer } from '@dataflow-animator/react';
import '@dataflow-animator/core/styles.css';

export default function Page() {
  return <DataFlowPlayer spec={spec} />;
}
```

## JSON auto-completion in VS Code {#autocomplete-json-vscode}

Add this configuration in `.vscode/settings.json` to enable auto-completion and inline validation on all your `*.dataflow.json` files:

```json title=".vscode/settings.json"
{
  "json.schemas": [
    {
      "fileMatch": ["*.dataflow.json"],
      "url": "./node_modules/@dataflow-animator/core/schema.json"
    }
  ]
}
```

The same path works with any JSON Schema draft-07 compatible validator (Ajv, ajv-cli, etc.). If you host the schema publicly, it can also be referenced from the [JSON Schema Store](https://www.schemastore.org/).

## SSR and hydration

The player renders **no markup on the server**. It mounts a framework-agnostic
DOM renderer in a client effect, so the static HTML holds a correctly-sized
placeholder and the diagram appears on hydration. There is no hydration mismatch
— there is nothing to match — and importing the package on a server is safe:
nothing touches the DOM at module scope.

What that costs you: a prerendered page shows an empty box where the diagram
will be. Use `fallback` to put something meaningful in the static HTML — a
poster image, a caption, a skeleton:

```tsx
<DataFlowPlayer spec={spec} fallback={<div>Loading animation...</div>} />
```

`NodeView` behaves the same way.
